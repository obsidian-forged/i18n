Obsidian i18n 把译文数据和目标插件目录分开保存。执行 **应用 / Apply** 时，插件先检查译文并准备备份，再把译文写入目标插件运行文件；执行 **还原 / Restore** 时，使用与当前插件版本匹配的备份恢复文件。

## 如何应用译文

<Steps>
  <Step title="打开管理中心">
    点击地球图标进入 `i18n 管理中心`。
  </Step>
  <Step title="找到目标插件">
    在顶部的 `插件` 标签中找到目标插件。
  </Step>
  <Step title="点击应用">
    点击 **应用 / Apply**。检查通过后，插件会把当前活动译文源映射到运行文件，并试运行目标插件；原先停用的插件在试运行后仍保持停用。
  </Step>
</Steps>

## 应用前的检查

从 2.0.26 起，插件译文至少需要一条原文、译文均非空且内容不同的 AST 或 Regex 条目。空字典、空规则或全部未翻译的条目会中止应用，不创建备份、不写入目标文件、不更新应用状态，也不重载目标插件。手动应用时会提示 **未检测到翻译内容**，请先在编辑器中完成翻译。

备份创建或读取失败时，当前应用会中止，不继续写入目标文件。请根据错误提示检查目标插件安装和备份是否可用，排查步骤见[故障排查](/help/troubleshooting)。

## 如何还原原始状态

点击插件右侧的 **还原 / Restore**。还原需要完整可读、来源版本与当前插件版本一致的备份。备份来源版本未知或与当前版本不一致时，会拒绝还原，避免旧文件覆盖新版插件。

如果提示还原失败，请先核对目标插件版本和错误信息。当前备份不可用时，可以从目标插件的发布渠道重新获取当前版本的原始文件，再处理译文。

<Warning>
  请保留 `${variable}` 中的原始表达式、顺序和 `\n` 等转义字符。AST 模式下，译文仍含插值但表达式发生变化时，该条会保留原文；完全删除所有插值可以生成静态文本并丢失动态值，不保证出现语法或重载错误。应用前应检查译文内容，不能仅凭重载成功判断变量完整。
</Warning>

## 应用失败后的恢复

目标插件试运行或重载失败时，插件会尝试从备份回滚，并检查原始插件能否重新加载。先查看回滚与重载结果，确认恢复成功后，再回到编辑器修改译文。

如果回滚或恢复后的重载仍失败，请停止重复应用，先恢复目标插件当前版本的原始文件并确认能正常加载。

## 智能更新

`automaticUpdate` 位于 **设置 → 社区插件 → I18N → 综合设置**，默认值为 `false`。

开启后，启动检查会比较已应用译文记录与目标插件版本，并尝试对版本已变化的插件重应用当前活动译文。

同版本重复应用会复用最初保存的原文；跨版本应用会基于当前插件文件重建备份。旧备份来源版本未知时会中止应用，备份失败时也不会继续写入。

## 为什么说译文与插件解耦

- 本地译文由 Obsidian i18n 自己管理
- 重装目标插件不会直接删除本地译文源
- 禁用 Obsidian i18n 不会自动清理已经写入目标插件的应用结果
