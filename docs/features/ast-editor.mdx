AST 编辑器处理的是已经提取出来的可翻译字符串，而不是目标插件源码。你不需要直接打开 `main.js` 搜索文本，插件会把命中的字符串显示成表格行。

## AST 提取是怎么工作的

AST 是 Abstract Syntax Tree（抽象语法树）的缩写。Obsidian i18n 会解析目标插件的编译产物 `main.js`，根据变量赋值、函数参数、对象键名和内容过滤规则提取文案；也能识别具有界面调用和显式英文语言目录证据的静态本地化字典。

<Note>
  提取需要目标插件目录中存在 `main.js`。提取结果和译文独立保存，提取操作不直接改写目标插件源码。
</Note>

## 如何提取字符串

<Steps>
  <Step title="打开管理中心">
    点击侧边栏地球图标，打开 `i18n 管理中心`。
  </Step>
  <Step title="找到目标插件">
    选择顶部的 `插件` 标签，按名称或 ID 找到已安装的目标插件。
  </Step>
  <Step title="提取并进入编辑器">
    在目标插件的更多菜单中执行 `提取译文`，生成本地译文源，再通过 `前往编辑器` 打开译文。
  </Step>
</Steps>

提取完成后，表格会显示节点类型、变量名、原文和译文列。

## 如何编辑译文

点击译文单元格即可修改。离开单元格后，内容会写回编辑器状态。开启 `综合设置 → 自动保存` 时，状态停止变化 500ms 后触发保存；未开启时，需要点击 `保存`。

- 可以连续编辑多行
- 可以用搜索框筛选条目
- 可以只看未翻译条目

<Tip>
  `未翻译` 筛选器会显示译文为空、只包含空白字符，或仍然等于原文的条目。
</Tip>

## 搜索与筛选

顶部搜索框会同时匹配：

| 维度 | 匹配内容 |
|------|----------|
| 节点类型 | 例如 `VariableDeclarator`、`CallExpression`、`LocalizationProperty` |
| 变量名 | 例如 `settingTitle`、`buttonLabel` |
| 原文 | 源文本 |
| 译文 | 当前已填写的目标语言文本 |

<AccordionGroup>
  <Accordion title="什么是节点类型？">
    表格类型表示提取时的上下文，包括变量声明 `VariableDeclarator`、赋值 `AssignmentExpression`、对象属性 `ObjectProperty`、函数调用 `CallExpression`、构造调用 `NewExpression` 和本地化字典属性 `LocalizationProperty`。
  </Accordion>
  <Accordion title="变量名有什么用？">
    变量名提供上下文，帮助你区分短文本在不同位置的实际用途。字典条目会保留对应的属性名。
  </Accordion>
</AccordionGroup>

## 本地化字典条目

从 2.0.27 起，已确认用于界面文案、并注册在多语言目录英文项中的静态字典可以生成 `LocalizationProperty` 条目。这是受限的识别规则，不会提取所有对象里的字符串。

这类译文只严格匹配已识别字典的属性值，不参与普通条目的全局宽松替换，从而保留字典查找键和下拉选项内部值。编辑时保留其节点类型、属性名和原文，只修改译文。

## 增量提取新增文案

已有译文文件缺少新文案时，可以在编辑器中执行 `增量提取`：

1. 如果当前译文已经应用，先回到管理中心执行 `还原`；已应用状态下不能增量提取。
2. 打开已有译文的 AST 编辑器，选择需要补充的文件。
3. 执行 `增量提取`，将新条目合并到现有条目中。相同类型、属性名和原文的已有条目保留原译文。
4. 筛选 `未翻译`，补充新条目的译文，保存后再应用。

升级后要使用新的字典提取能力，也需要对缺少这些条目的已有译文执行提取。增量提取中新增但尚未翻译的 `LocalizationProperty` 不会盖过旧类型条目的有效译文。
