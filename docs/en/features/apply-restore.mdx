Obsidian i18n keeps translation data separate from the target plugin directory. Clicking **应用 / Apply** checks the translation and prepares a backup before writing the target plugin files. Clicking **还原 / Restore** recovers files from a backup that matches the current plugin version.

## Apply a translation

<Steps>
  <Step title="Open the Manager">
    Click the globe icon to open `i18n 管理中心`.
  </Step>
  <Step title="Choose the target plugin">
    In **插件**, find the installed plugin whose active translation you want to apply.
  </Step>
  <Step title="Apply the translation">
    Click **应用 / Apply**. After the checks pass, the plugin writes the active translation and test-loads the target plugin. A plugin that was disabled remains disabled after the test load.
  </Step>
</Steps>

## Checks before applying

Starting with 2.0.26, a plugin translation needs at least one AST or Regex entry with non-empty, different source and target text. An empty dictionary, empty rules, or entirely untranslated entries stop the operation before backup creation, target-file writes, application-state changes, or plugin reload. Manual apply shows **未检测到翻译内容**; complete the translation in the editor first.

If backup creation or reading fails, the current apply stops before writing target files. Use the error to check the target installation and backup availability. See [Troubleshooting](/en/help/troubleshooting) for the recovery steps.

## Restore the original state

Click **还原 / Restore**. Restoration requires a complete, readable backup whose recorded source version matches the current plugin version. An unknown or different source version blocks restoration to prevent older files from overwriting a newer plugin.

If restoration fails, check the target plugin version and the reported error. When the current backup is unavailable, obtain the original files for the current version from the target plugin's release channel before continuing with translation work.

<Warning>
  Keep the original expressions and order inside `${variable}`, along with escape sequences such as `\n`. In AST mode, an entry keeps its original text when the translation still contains interpolation but changes its expressions. Removing all interpolation can produce static text and lose dynamic values without a syntax or reload error. Check the translation before applying; a successful reload does not prove that placeholders are intact.
</Warning>

## Recovery after an apply failure

If the target plugin fails its test load or reload, the plugin attempts to roll back from the backup and checks whether the original plugin can load again. Check the rollback and reload results before returning to the editor to revise the translation.

If rollback or the subsequent reload fails, stop repeated apply attempts. Restore the target plugin's original files for its current version and confirm that it can load first.

## Automatic re-apply after target updates

`automaticUpdate` is in **Settings → Community Plugins → I18N → 综合设置** and defaults to `false`.

When enabled, startup checks compare the applied-translation record with the target plugin version and attempt to re-apply the active translation when that version has changed.

Repeated apply operations for the same version reuse the original saved source. Applying across versions rebuilds the backup from the current plugin files. An unknown old backup version stops the apply operation, and a backup failure also prevents further writes.

## Why translations are separate from plugins

- Obsidian i18n manages local translations separately.
- Reinstalling the target plugin does not directly delete its local translation sources.
- Disabling Obsidian i18n does not automatically remove translations already written into the target plugin.
