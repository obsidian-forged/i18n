Automation is not configured in `综合设置`. The current entry point is the Manager view's **自动化** tab, rendered by `AutoManagerPanel`.

<Note>
  When `autoDiscovery` is enabled, the plugin runs discovery on startup and also checks every 30 minutes whether `autoCheckInterval` has elapsed.
</Note>

## Defaults

| Field | Default | Meaning |
|------|---------|---------|
| `autoDiscovery` | `false` | background discovery enabled or disabled |
| `autoMatchStrategy` | `comprehensive` | scoring strategy |
| `autoApply` | `false` | apply matches during a manually started `探测扫描` run |
| `autoCheckInterval` | `24` | interval in hours; `0` disables scheduled checks |
| `autoTrustedRepos` | `[]` | trusted repositories |
| `autoExcludeList` | `[]` | excluded plugin IDs |
| `autoScanMode` | `incremental` | scan mode |

## Turn it on

<Steps>
  <Step title="Open the Manager">
    Click the globe icon to open the Obsidian i18n Manager.
  </Step>
  <Step title="Open Automation">
    Switch to the **自动化** tab.
  </Step>
  <Step title="Enable background discovery">
    Turn on **后台探测与通知**. This enables `autoDiscovery`.
  </Step>
  <Step title="Set the interval">
    Enter the interval in hours under **探测周期**. `0` disables scheduled checks.
  </Step>
  <Step title="Choose scan scope">
    `autoScanMode` supports `incremental` and `full`.
  </Step>
</Steps>

## Match scoring

When multiple cloud translations exist for the same target, `autoMatchStrategy` rescoring picks the highest score. The current implementation builds the base score from:

- **version compatibility**: up to 50 points
- **popularity**: up to 30 points
- **freshness**: up to 20 points

For plugins, raw version compatibility is:

- exact `supported_versions` match: 100
- same major version: 50
- anything else: 0

For plugins, raw values of `100 / 50 / 0` become `50 / 25 / 0` version points. Themes use a fixed raw value of `50`, which contributes `25` version points.

<AccordionGroup>
  <Accordion title="comprehensive (default)">
    total = version + popularity + freshness
  </Accordion>
  <Accordion title="version_first">
    total = `1.5 × version + 0.5 × popularity + 0.5 × freshness`, capped at 100
  </Accordion>
  <Accordion title="popularity">
    total = `0.5 × version + 1.5 × popularity + 0.5 × freshness`, capped at 100
  </Accordion>
  <Accordion title="latest_update">
    total = `0.5 × version + 0.5 × popularity + 1.5 × freshness`, capped at 100
  </Accordion>
</AccordionGroup>

## Auto-apply

Background discovery triggered on startup or by scheduled checks skips results that are already up to date and keeps matches requiring action in the reviewable task list. Turning on **自动应用翻译** (`autoApply`) does not make background discovery download and apply these translations.

When you manually click **探测扫描**, `autoApply=false` keeps matches for review. For matches that are not already up to date, `autoApply=true` proceeds to apply the translation, downloading it first when the local cache does not match. Click **一键审阅** to apply previously discovered tasks as a batch.

<Warning>
  `autoApply` is disabled by default. Automation only reads registries from repositories listed in `autoTrustedRepos`, and repository values must use `owner/repo` format.
</Warning>

## Trusted repositories and exclusions

<AccordionGroup>
  <Accordion title="autoTrustedRepos: trusted repositories">
    Automation only scans translation registries in these repositories. An empty list leaves no repositories available for automatic application.
  </Accordion>

  <Accordion title="autoExcludeList: excluded plugin IDs">
    Listed plugin IDs are skipped during automatic discovery, matching, and application.
  </Accordion>
</AccordionGroup>
