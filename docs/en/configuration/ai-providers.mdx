## Add a provider profile

<Steps>
  <Step title="Open the 语言模型 tab">
    Go to **Settings → Community Plugins → I18N → `语言模型`**.
  </Step>
  <Step title="Choose a provider">
    Choose the target platform from the provider dropdown.
  </Step>
  <Step title="Create or switch a profile">
    The UI supports adding, switching, and deleting profiles.
  </Step>
  <Step title="Fill in connection fields">
    Check the profile's URL, API key, and model ID. Initial presets do not guarantee a provider's current model availability; custom endpoints and local models require their actual connection details.
  </Step>
  <Step title="Run connection testing">
    Click the test button and inspect the diagnostic result.
  </Step>
</Steps>

## Fields on this page

<AccordionGroup>
  <Accordion title="URL / API Key / Model">
    These are independently stored in the active provider profile. Cloud OpenAI-compatible endpoints and local services support model-list refresh; you can still enter a model ID manually when no list is available.
  </Accordion>
  <Accordion title="自定义价格 (custom pricing)">
    `useCustomPrice` controls whether to use the profile's custom input rate. Both `priceInput` and `priceOutput` are stored in CNY per million tokens, but the current estimate uses only an enabled custom `priceInput` greater than zero; otherwise it falls back to a built-in model input rate. `priceOutput` currently does not affect the estimate.
  </Accordion>
  <Accordion title="响应格式 (response format)">
    `llmResponseFormat` is global and defaults to `text`. OpenAI-compatible translation requests can select `text`, `json_object`, or `json_schema`; actual diagnostic results determine whether a model accepts the format.
  </Accordion>
  <Accordion title="推理强度 (reasoning effort)">
    `llmReasoningEffort` is global and defaults to `none`. Values are `none`, `low`, `medium`, `high`, and `auto`. OpenAI-compatible translation requests send the selected `reasoning_effort`; choosing `auto` omits the parameter and leaves the decision to the provider. Support varies by model, and choosing `none` does not guarantee that every provider disables reasoning.
  </Accordion>
</AccordionGroup>

## Parameter compatibility and diagnostics

When connection diagnostics receive HTTP `400` or `422` with an error explicitly rejecting `reasoning_effort`, they remove that field and retry once. Later requests in the same diagnostic run omit it; a new run probes it again. This fallback does not suppress other errors.

OpenAI-compatible batch translation requests also handle recognized parameter-rejection errors by removing the parameter and retrying. This does not establish compatibility for every model's format, reasoning output, or translation quality; inspect the diagnostics and actual translations.

## Fields edited elsewhere

These global translation fields are read and written by the AST / Regex / Theme AI panels:

- target language: `language` / `llmLanguage`
- translation style: `llmStyle`
- rows per batch: `llmBatchSize`
- concurrent requests: `llmConcurrencyLimit`
- timeout: `llmTimeout`

<Note>
  Ollama defaults to `http://localhost:11434`. Local Ollama does not require an API key; configure other local compatible services according to their authentication requirements.
</Note>
