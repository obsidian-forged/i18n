## 添加一个服务商方案

<Steps>
  <Step title="打开语言模型标签页">
    进入 **设置 → 社区插件 → I18N → 语言模型**。
  </Step>
  <Step title="选择服务商">
    在服务商下拉框中选择目标平台。
  </Step>
  <Step title="创建或切换方案">
    当前 UI 支持新增、切换和删除方案。
  </Step>
  <Step title="填写连接信息">
    核对方案的 URL、API Key 和模型 ID。内置初始值不是服务商当前可用模型的保证；自定义接口和本地模型需要填写实际连接信息。
  </Step>
  <Step title="执行测试连接">
    点击测试按钮，查看连接诊断结果。
  </Step>
</Steps>

## 当前页中的关键字段

<AccordionGroup>
  <Accordion title="URL / API Key / Model">
    这些字段属于当前服务商方案，彼此独立保存。云端 OpenAI 兼容接口和本地服务支持刷新模型列表；无法取得列表时仍可手动填写模型 ID。
  </Accordion>
  <Accordion title="自定义价格">
    `useCustomPrice` 控制是否使用方案的自定义输入价。`priceInput`、`priceOutput` 均以人民币 / 每百万 Token 保存，但当前费用估算仅使用大于 0 的自定义 `priceInput`；否则回退到内置模型输入价。`priceOutput` 当前不参与估算。
  </Accordion>
  <Accordion title="响应格式">
    `llmResponseFormat` 是全局字段，默认值为 `text`。OpenAI 兼容翻译请求可选择 `text`、`json_object` 或 `json_schema`；模型是否接受对应格式需要通过实际诊断确认。
  </Accordion>
  <Accordion title="推理强度">
    `llmReasoningEffort` 是全局字段，默认值为 `none`。可选值为 `none`、`low`、`medium`、`high` 和 `auto`。OpenAI 兼容翻译请求会发送所选的 `reasoning_effort`；选择 `auto` 时省略该参数，交由服务商决定。模型对这些值的支持不一致，选择 `none` 不保证所有服务商都能关闭推理。
  </Accordion>
</AccordionGroup>

## 参数兼容与连接诊断

连接诊断收到 HTTP `400` 或 `422`，且错误明确拒绝 `reasoning_effort` 时，会移除该字段重试一次，并在本轮后续诊断中省略它；新一轮诊断会重新探测。其他错误不会因此被忽略。

OpenAI 兼容的批量翻译请求也有识别参数拒绝后移除参数重试的处理。这不能证明所有模型的格式、推理输出和译文质量都兼容；请按实际诊断结果和译文检查。

## 不在当前页直接编辑的字段

下面这些全局翻译参数由 AST / Regex / Theme 的 AI 面板读写：

- 目标语言：`language` / `llmLanguage`
- 翻译风格：`llmStyle`
- 每批条目数：`llmBatchSize`
- 并发请求数：`llmConcurrencyLimit`
- 超时时间：`llmTimeout`

<Note>
  Ollama 默认地址是 `http://localhost:11434`。本地 Ollama 不需要 API Key；其他本地兼容服务按其认证要求配置。
</Note>
